# ผลแก้ไขระบบใบเสร็จและ OCR — 14 พฤศจิกายน 2026

ปรับระบบตาม audit วันที่ 12 พฤศจิกายนแล้วในโค้ด และเพิ่ม PaddleOCR แบบใช้โมเดลสำเร็จรูป ไม่มีบริการ OCR ที่คิดค่าต่อใบหรือการเทรนโมเดลใหม่ การนำขึ้นระบบจริงและการยืนยันความแม่นยำบนใบเสร็จจริงยังเป็นงานคนละส่วนกับการแก้โค้ดครั้งนี้

## เส้นทางใช้งาน

ถ่าย/เลือกรูป → เก็บไฟล์ต้นทาง → กล่องเอกสารใน SQLite → OCR บนเครื่อง หรือเลือกส่งไป PaddleOCR ของเราเอง → ตรวจข้อมูลรายช่อง → แก้เฉพาะข้อยกเว้น → ยืนยันหลายใบ → บันทึกด้วยคำสั่งที่ลองต่อได้ → ซิงก์รูปและข้อมูล → ส่งออกให้นักบัญชี / สำรองและกู้คืน

ML Kit เป็นตัวอ่านเริ่มต้นบนมือถือ ส่วน PaddleOCR ต้องมีบริการที่เราดูแลเองและผู้ใช้เลือก Read with PaddleOCR จึงจะส่งภาพ การตั้งค่า URL อย่างเดียวไม่เปิดการส่งรูปอัตโนมัติ ไม่มีการติดตั้ง PaddleOCR บนมือถือหรือเปิดโฮสต์สาธารณะให้โดยอัตโนมัติ

## สิ่งที่แก้ตาม audit

| ข้อ | ผลแก้ไข |
|---|---|
| F1 ใบผสม | แยกสัญญาณสินค้าส่วนตัวกับค่าน้ำมัน และขวางการยืนยันจนจัดสรรยอดที่ยังไม่ชัด; การเปิดฟอร์มแล้วกดบันทึกไม่ล้างปัญหานี้ |
| F2 สกุลเงิน | มี currency จริง; ไม่ทราบ/เงินต่างประเทศไม่ถูกบันทึกเงียบ ๆ เป็น AUD; ยังไม่มีการแปลงค่าเงินอัตโนมัติ |
| F3 แก้ไขและประวัติ | เก็บค่าเดิม/ค่าใหม่ แหล่งที่มา เวลา และ revision; แก้ข้อมูลแล้วคำยืนยันเดิมหมดผล; ตรวจใหม่ก่อน commit |
| F4 รูปและความต่อเนื่อง | ตรวจเปิดรูปจริงและ fingerprint ทุกหน้า; การเปลี่ยนรูปต้องตรวจใหม่และอัปเดต page hashes พร้อมกัน |
| F5 ลบข้อมูล | ครอบคลุม inbox ใหม่ เอกสารบันทึกแล้ว ไฟล์เก่า และดัชนีเก่าที่ระบุเจ้าของได้ รวมกรณีดัชนีเก่าเสียหายของรถที่ทราบ |
| F6 Backup | ZIP รุ่นใหม่รวมรูป ฉบับร่าง และข้อมูลแอป; ตรวจ hash/ขนาด/เส้นทางก่อน merge; มี journal ให้ลองต่อเมื่อกู้คืนค้าง |
| F7 บันทึกเป็นระบบ | SQLite สำหรับเอกสาร รุ่นข้อมูล และ commit intents; กันการเขียนทับ revision เก่าและการ replay คำยืนยันเก่าหลังแก้ไข; บัญชีรายจ่ายเดิมยังเก็บแบบเดิมเพื่อไม่เปลี่ยนยอดย้อนหลัง |
| F8 หลายหน้าและ retry | รวม/แยกหน้าได้โดยไม่บวกยอดหน้าเอง; เก็บสถานะอ่านล้มเหลวและลองใหม่; ออกจากหน้าจอแล้วกลับมาทำต่อได้ ไม่ใช่ OS background worker |
| F9 ความมั่นใจ | คะแนนกฎไม่ถูกแสดงว่าเป็นอัตราความแม่นยำจริง; machine extraction ไม่สร้างการยืนยันโดยมนุษย์; เก็บ engine/version/ตำแหน่งข้อความ |
| F10 กฎกลาง | ใช้นโยบายตรวจร่วมกันหลังอ่าน หลังแก้ และก่อนบันทึก; วันที่ซื้อไม่ทราบยังเป็นข้อยกเว้น; ไม่เติม GST เพื่อให้ตรงสูตร |
| F11 ส่งออก/ซิงก์ | เพิ่มร้าน สกุลเงิน GST ABN เลขใบเสร็จ revision/เวลา และ audit events; รองรับรูปหลายหน้า; แสดงจำนวนฉบับร่างที่ยังไม่อยู่ในยอด |
| F12 บัญชีและรถ | Inbox รวมระดับบัญชี ค้นพบดัชนีเก่าที่ตรวจเจ้าของได้ เลือกรถ/ทริปตามบริบทเอกสาร ย้ายฉบับร่าง Guest และกันเปลี่ยนบัญชีระหว่าง restore |

คำยืนยันผูกกับค่าที่ตรวจจริง ไม่ใช่เพียงเลข revision: เปลี่ยนยอดแล้วนำ audit เก่ากลับมาใช้จะถูกปฏิเสธ คำสั่งบันทึกที่ค้างจะถูกยกเลิกเมื่อเอกสารถูกแก้ไข ไม่ย้อนกลับมาบันทึกค่าเก่าหลังเปิดแอปใหม่

## PaddleOCR และการเปรียบเทียบ

- ใช้ PaddleOCR 3.3.2 กับโมเดล PP-OCRv5 สำเร็จรูปบน CPU ผ่านบริการ Python ที่ต้องใช้ token
- รันโมเดลจริงสำเร็จ และทดสอบตัวอ่าน Flutter ผ่าน HTTP ไปยังบริการจริงแล้ว
- ทดสอบ ML Kit จริงบน iPhone Simulator ด้วยภาพเดียวกันด้วย
- พบว่า ML Kit ส่งคอลัมน์ชื่อรายการก่อนคอลัมน์จำนวนเงิน จึงเพิ่มการเรียงแถวตามตำแหน่งบนภาพก่อนแปลยอด/GST พร้อม regression test
- ชุดตัวอย่างมี **ภาพสังเคราะห์หนึ่งภาพ** ทั้งสอง engine มีผลอ่านจริงเก็บไว้ และใช้ parser/นโยบายตรวจชุดเดียวกัน สรุปอยู่ใน `tool/paddle_ocr/benchmark-synthetic-report.json`
- ยังไม่มีชุดใบเสร็จจริงที่คนตรวจคำตอบแล้ว จึงไม่อ้างความแม่นยำใช้งานจริง ความเหนือกว่าของ engine หรือเวลาที่คนประหยัดได้ คะแนนทดสอบภาพเดียวไม่ใช่เปอร์เซ็นต์ความแม่นยำของผลิตภัณฑ์

เลข ABN บนภาพสังเคราะห์จงใจไม่ผ่าน checksum ผลที่ถูกต้องจึงต้องส่งตรวจ แม้ตัวอักษรถูกอ่านครบ

## ผลตรวจ

- ชุดหลัก: 118 กรณีผ่าน ครอบคลุม capture/review/commit, SQLite, backup, export, sync และกรณีเสียหาย/ลองใหม่
- ชุด inbox/auth/account cleanup เพิ่มเติม: 18 กรณีผ่าน (บางกรณีซ้ำกับชุดหลัก)
- หลังแก้การเรียงข้อความและเพิ่มกรณีลบดัชนีเสียหาย: ชุดเฉพาะ 16 กรณีผ่าน
- Python: 4 กรณีผ่าน รวมความปลอดภัย endpoint และ benchmark ที่ไม่ตัดภาพที่ไม่มีผลอ่านออกจากตัวหาร
- HTTP จริง Flutter → PaddleOCR: ผ่านหนึ่งกรณี
- ML Kit บน iPhone Simulator หลังแก้การจัดแถว: ผ่านหนึ่งกรณี รวม assertion ยอด GST สกุลเงิน และวันที่
- iOS Simulator build: ผ่าน
- มีการตรวจทานแยกและแก้ประเด็น stale commit, legacy cleanup, account-switch race และรูปทดแทน

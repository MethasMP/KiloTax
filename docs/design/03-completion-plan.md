## เฟส 2A — ย้ายสี hex → `AppColor` ✅ **เสร็จแล้ว**

**ทำไม:** เดิมมีสี hex เขียนสด **305 จุด / 76 ค่า** ใน 46 ไฟล์ ทำให้เปลี่ยนธีมทีต้องแก้ 305 ที่

**ผลที่ได้ (วัดจากโค้ดจริง):**

| | ก่อน | หลัง |
|---|---|---|
| สี hex เขียนสดทั้ง `lib/` | 305 | **62** |
| สี hex ใน `lib/ui/**` (ชั้น UI) | ~190 | **1** (เป็น shadow alpha → ยกไปเฟส 2C) |
| ที่เหลือ 62 | — | 47 = นิยาม token ใน `app_color.dart` · 10 = `app_constants.dart` (legacy รอ 2B/2C) · 4 = เงาใน `app_space.dart` |

**ทำอย่างไร:**
1. Codemod แทน **115 จุด** ที่ตรงกับ token เป๊ะ (รอบนี้ **พิกเซลเหมือนเดิม 100%** — ตรวจด้วย pixel diff เทียบ baseline)
2. เพิ่ม token ใหม่ 12 ตัวที่ขาด: `surfaceSunken`, `navyRaised`, `navyLine`, `positiveBright`,
   `positiveTintStrong`, `attentionTintSoft`, `attentionTintStrong`, `criticalTintStrong`,
   `navy800/700/600/500/400/300/200`, `cyan400`, `red400`, และ `scrimSoft/Medium/Strong`
3. Codemod รอบที่สองแทน **148 จุด** โดยรวมสีที่ซ้ำซ้อนเข้าหากันอย่างมีเจตนา:
   - สีเขียว 2 เฉด (`10B981`, `34D399`) → `positiveBright` (ใช้เฉพาะบนพื้นเข้ม)
   - สีส้ม 3 เฉด (`F97316`, `EA580C`, `C2410C`) → ตระกูล `attention`
   - สีม่วง (`9333EA`) → `brand` (ตัดสีที่ไม่อยู่ในพาเลตต์ออก)
   - **สีนาวี 2 ค่า** (`0F172A`, `0B132B`) → `surfaceNavy` (แก้ปัญหาที่ audit ตั้งข้อสังเกตว่ามี "navy สองค่า")
   - **alpha ดำ 8 ค่า** (4%, 6%, 10%, 12%, 16%, 24%, 26%, 32%) → `scrimSoft/Medium/Strong` 3 ระดับ
   - `CBD5E1` (Slate 300, contrast 1.55:1) → `line` (Slate 400, 3.02:1) — ขอบมองเห็นได้ขึ้น
4. ตรวจผลด้วย **pixel diff** เทียบ baseline: 5 หน้าจอเปลี่ยน รวม 89,074 px (1.2%) ซึ่งเป็นการรวมสีที่ตั้งใจ
   และตรวจด้วยตาทีละจอแล้วว่าไม่มีจอไหนแย่ลง — การเปลี่ยนสีเขียวทั้งหมดอยู่บนพื้น navy ซึ่งสีอ่อนกว่าถูกต้อง

**เกณฑ์เสร็จ:** `grep -rc "Color(0x" lib/ui` = 1 (เหลือ shadow alpha 1 จุด) ✅
**การยืนยัน:** 219/219 เทสต์ผ่าน · `flutter analyze lib/` สะอาด · overflow 0 จุด ทุกหน้าจอและทุก text scale

## เฟส 2B — ย้าย `TextStyle` → `AppType`

**ทำไม:** 576 จุดที่เขียน `fontSize`/`fontWeight` เอง คือต้นเหตุที่ขนาดฟอนต์เคยบานไป 27 ระดับ
ตอนนี้ `AppType` มี 9 ระดับพร้อมใช้แล้ว แต่ยังไม่มีหน้าจอไหนใช้

**วิธีที่ปลอดภัย (สำคัญ):** **ห้าม** หา-แทนที่ `fontSize: 13` ตรง ๆ เพราะ `13` เดียวกันอาจต้องกลายเป็นคนละ tier
ให้ทำแบบนี้แทน:

1. เขียนสคริปต์ที่ **สแกนและรายงาน** ก่อน — จับคู่ `(fontSize, fontWeight)` ที่อยู่ด้วยกัน แล้วเสนอ tier ที่ใกล้ที่สุด
   ```bash
   # ตัวอย่างผลลัพธ์ที่ต้องได้ก่อนแก้
   # 13/w500  -> AppType.secondary      พบ 41 จุด
   # 16/w600  -> AppType.cardTitle      พบ 22 จุด
   # 42/w900  -> AppType.metric         พบ  1 จุด
   # 13.5/w800-> ไม่มี tier ตรง -> ต้องตัดสินใจ
   ```
2. ตรวจรายการที่ "ไม่มี tier ตรง" ด้วยตาก่อน — นี่คือจุดที่การออกแบบต้องตัดสินใจ ไม่ใช่สคริปต์
3. แทนที่เฉพาะคู่ที่ชัดเจน แล้วเรนเดอร์ภาพเทียบทีละจอ
4. ที่เหลือ (ขนาดครึ่งพิกเซล 133 จุด) แปลงเป็น tier ที่ใกล้ที่สุด — **นี่คือจุดที่ภาพจะเปลี่ยน** จึงต้องตรวจทีละจอ

**เกณฑ์เสร็จ:** `grep -rc "fontSize:" lib/ui` เหลือเฉพาะในไฟล์ theme และภาพทุกจอยังถูกต้อง

**กับดักที่ต้องระวัง:** `letterSpacing` ที่ผูกกับขนาดเดิม (เช่น `-1.6` คู่กับ 44px) ต้องถูกดูดเข้าไปใน tier ด้วย ไม่งั้นตัวอักษรจะห่างผิด

## เฟส 2C — ย้าย spacing / radius / เงา

| สิ่งที่เขียนสด | จำนวน | เป้าหมาย |
|---|---|---|
| `EdgeInsets.*` | 381 | `S.gutter`, `S.cardPad`, ค่าจาก `S` |
| `BorderRadius.circular()` | 350 | `R.chip` (8) / `R.control` (10) / `R.card` (16) / `R.sheet` (24) |
| `SizedBox(height/width:)` | 613 | ค่าจาก `S` (กริด 4pt) |
| `boxShadow:` | 49 | `AppElevation.card` / `.floating` / `.overlay` |

**ลำดับที่ให้ผลเร็วที่สุด (ทำ 3 อย่างนี้ก่อน จะเห็นภาพทันที):**
1. **`S.cardPad`** — padding ในการ์ดเคยมี 4 ค่า (22/20, 20, 16, 14) ทำให้ขอบข้อความในการ์ดที่เรียงต่อกันไม่ตรง
   → บังคับเป็น `S.cardPad` (20) ทั้งหมด แล้วภาพจะ "เข้าที่" ทันที
2. **รัศมี 4 ค่า** — ตอนนี้มี 19 ค่า โดย 10/12/14/16/18/20 ใช้หนักพอกันหมด
3. **`AppElevation`** — เงา 49 สูตร เริ่มจาก nav bar (`AppShadows.floatingNav` ที่ตายอยู่) และการ์ด 6 จุด

**เกณฑ์เสร็จ:** จำนวน `BorderRadius.circular` ที่ไม่ซ้ำ ≤ 5, จำนวน `boxShadow` ลดลง ≥ 30 จุด, การ์ดทุกใบ padding เท่ากัน

### 3.3 · Splash screen (mockup หน้าจอ 1)
**ปัญหา:** ไม่มีเลย → ตอนเปิดแอปมีจอว่าง/ขาวระหว่าง `AppState.init()`
**ทำอะไร:** หน้าจอที่มีโลโก้แบรนด์ + แสดงระหว่าง initialise จริง (ไม่ใช่หน่วงเวลาปลอม)
**เกณฑ์เสร็จ:** เปิดแอปแล้วไม่เห็นจอขาวว่าง

### 3.4 · Loading / empty / error state
**ปัญหา:** `appState.isInitialized` มีอยู่แล้ว (`app_state.dart:102`) แต่ **ไม่มีหน้าจอไหนอ่าน** →
"โหลดช้า" กับ "ไม่มีข้อมูล" หน้าตาเหมือนกันเป๊ะ และ `restoreFromCloud()` ทิ้งผลลัพธ์ (ดึงล้มเหลว = เงียบ)
**ทำอะไร:** ① ประตูโหลดระดับแอป ② skeleton ที่มีรูปทรงตรงกับเนื้อหา ③ แบนเนอร์ offline ④ แสดง error เมื่อ cloud restore ล้มเหลว
**เกณฑ์เสร็จ:** จำลอง restore ล้มเหลวได้ แล้วผู้ใช้เห็นข้อความ + ปุ่มลองใหม่ (ไม่ใช่ empty state)

### 3.5 · `intl` + รูปแบบตัวเลข/วันที่
**ปัญหา:** `Formatters` เขียน regex เอง, `dateTime()` **ไม่มีปี** → บันทึกภาษีแยกไม่ออกระหว่างปี
**ทำอะไร:** ใช้ `NumberFormat.currency(locale: 'en_AU')` + `DateFormat` และเพิ่มปีใน `dateTime()`
**เกณฑ์เสร็จ:** "12 Sep 2026, 8:42 am" และตัวเลขผ่าน locale จริง
**กับดัก:** เทสต์ `formatters` ที่ผูกกับรูปแบบเดิมจะพัง — ต้องแก้พร้อมกัน

### 3.6 · Reduce-motion
**ปัญหา:** token พร้อมแล้ว (`AppMotion.respecting`) แต่ยังไม่ต่อเข้า widget — ผู้ใช้ที่เปิด Reduce Motion ยังได้แสงวิ่ง 1400ms และ `..repeat(reverse: true)` ที่วิ่งตลอด
**เกณฑ์เสร็จ:** เปิด Reduce Motion แล้ว animation ทั้งหมดหยุด/สั้นลงจริง

### 3.7 · ล้าง token ที่ไม่ใช้
- `darkSurface`, `darkBorder`, `textSecondaryDark` — **ลบ** (ตัด dark mode ออกจากขอบเขตแล้ว)
- `telemetryReady`, `telemetryReadyLight`, `telemetryLive`, `telemetryLiveLight` — **ลบ** (ไม่เคยถูกเรียก, ซ้ำกับ `brandElectric`/`emerald` เป๊ะ)
- มี usages 9 จุดที่ใช้ `dark*` อยู่ → เปลี่ยนเป็นสี light theme
- `location_escalation_dialog.dart:41` พ่น `deepNavy` ทับทั้งหน้า → เปลี่ยนเป็นพื้นสว่าง (ไม่งั้นมันคือ dark mode แอบแฝง)
**เกณฑ์เสร็จ:** `AppColors` ไม่มี token ที่ไม่มีใครใช้

# เจาะลึก OpenThai OCR: ทำไมถึงแม่นยำกว่าเจ้าอื่นๆ สำหรับภาษาไทย

**OpenThai OCR** (พัฒนาโดย **iApp Technology** และเครือข่ายพันธมิตร OpenThai / AIEAT) ได้รับการยอมรับอย่างกว้างขวางว่าเป็นหนึ่งในเครื่องมือ Thai OCR ที่แม่นยำและตอบโจทย์งานเอกสารภาษาไทยได้ดีที่สุดในปัจจุบัน เมื่อเทียบกับทั้ง Global Open-source OCR (เช่น Tesseract, EasyOCR, PaddleOCR) และโซลูชันทั่วไป

บทความนี้สรุปปัจจัยเชิงสถาปัตยกรรม (Architecture), ชุดข้อมูล (Dataset & Training), และการแก้ปัญหาเฉพาะจุดของภาษาไทย (Linguistic Challenges) ที่ทำให้ OpenThai OCR มีความแม่นยำสูง

---

## 1. จุดอ่อนของ OCR ทั่วไปเมื่อเจอกับ "ภาษาไทย"

ภาษาไทยเป็นภาษาที่ OCR ทั่วไป (เช่น Tesseract หรือ Multilingual OCR ทั่วโลก) มักจะล้มเหลวเนื่องจากลักษณะเฉพาะ 4 ประการ:
1. **โครงสร้าง 4 ระดับ (4-Level Stacking):** พยัญชนะ + สระบน + วรรณยุกต์ (เช่น `กิ่`) หรือ สระล่าง (`กุ`) OCR ทั่วไปมักตรวจจับสระลอย/วรรณยุกต์หลุด บิดเบี้ยว หรือตัดคำผิดบรรทัด
2. **ฟอนต์ไม่มีหัว (Loopless Fonts):** ฟอนต์สมัยใหม่ (Prompt, Kanit, Sukhumvit Set) ตัวอักษรเช่น `ด`, `ค`, `ต`, `ล`, `บ` มีเส้นฐานใกล้เคียงกันมาก หากเทรนมาเฉพาะฟอนต์ราชการ (TH Sarabun) จะเกิด Error สูงมาก
3. **ไม่มีช่องไฟเว้นวรรคระหว่างคำ (No Word Delimiters):** เขียนติดกันเป็นพืด การหา Bounding Box และ Sequence Prediction ต้องเข้าใจบริบทคำศัพท์
4. **โครงสร้างเอกสารราชการ/ตารางซับซ้อน (Complex Tables & Forms):** กฎหมาย, หนังสือราชการ, ราชกิจจานุเบกษา มักมีตารางแยกคอลัมน์หลายชั้น ซึ่ง OCR ดั้งเดิมจะอ่านข้ามคอลัมน์ ทำให้เนื้อหาเละ

## 2. ทำไม OpenThai OCR ถึงแม่นยำและเหนือกว่าเจ้าอื่น?

### 2.1 สถาปัตยกรรมแบบ Dual-Path ที่ออกแบบมาเพื่อแก้ปัญหาเฉพาะทาง
OpenThai OCR (รุ่น 2.0 และ 2.1) แบ่งโมเดลออกเป็น 2 แนวทางชัดเจนตาม Use-case:

1. **OpenThai OCR Text (Lightweight Pipeline):**
   - **ขนาดเล็กมาก:** ~1.02M พารามิเตอร์ (ขนาดไฟล์เพียง 4.2 MB – 6.6 MB)
   - **สถาปัตยกรรม:** แยก **Text-line Detector (~1.8 MB)** และ **Thai Line Recognizer (~2.4 MB)** ออกจากกัน พร้อมปรับแต่ง Output Layer ให้รองรับการเรียงสระ/วรรณยุกต์ภาษาไทยโดยเฉพาะ
   - **ความเร็ว & ความแม่นยำ:** ทำงานบน CPU ได้เต็มประสิทธิภาพ (ประมาณ ~0.39 วินาทีต่อหน้า A4) ไม่ต้องพึ่งพา GPU ช่วยลดปัญหา Hallucination ของ Generative Model ในงานดึงข้อความระดับบรรทัด

2. **OpenThai OCR Markdown (Vision-Language / Document Parser):**
   - **สถาปัตยกรรมระดับ 0.63B พารามิเตอร์:** นำ Foundation Parse Model (เช่น NVIDIA Nemotron Parse / Vision-Language Architecture) มา Fine-tune เฉพาะทาง
   - **โครงสร้างเอกสารถูกรักษา 100%:** ไม่เพียงแต่อ่านตัวหนังสือ แต่แปลง Layout ออกมาเป็น Markdown/HTML
     - ตารางที่ซับซ้อนถูกแปลงเป็นแท็ก HTML (`<table>`, `<tr>`, `<td>`, รองรับ `rowspan` และ `colspan`)
     - ลำดับการอ่าน (Reading Order) ในเอกสารหลายคอลัมน์ถูกต้อง ไม่ผสมข้ามคอลัมน์
     - รองรับสูตรคณิตศาสตร์ (LaTeX) และแยก Header/Footer ออกจากเนื้อหาหลัก

### 2.2 ชุดข้อมูลฝึกฝนภาษาไทยที่เฉพาะเจาะจง (Domain-Specific Dataset)
- **ข้อมูลจริงกว่า 410,000+ บรรทัด (ในเวอร์ชัน 2.0):** มุ่งเน้นไปที่เอกสารไทยที่มีปัญหาบ่อย เช่น พระราชกิจจานุเบกษา, หนังสือเวียนราชการ, เอกสารสัญญา, คำพิพากษาศาล
- **ขยายสู่เอกสาร 9 หมวดหมู่ในเวอร์ชัน 2.1:** ได้แก่ เอกสารวิชาการ, หนังสือเรียน, ตำรา, แบบทดสอบ/ข้อสอบ, นิตยสาร, หนังสือพิมพ์, รายงานประจำปีบริษัท, สไลด์พรีเซนต์ และการ์ตูน/ช่องคำพูด
- **รองรับภาพถ่ายจากมือถือ (In-the-wild Phone Captures):** มีการ Augmented ข้อมูลที่มีแสงสะท้อน, กระดาษยับ, มุมเอียง, และภาพเบลอ ทำให้ทนทานต่อภาพเอกสารจริงมากกว่า OCR ที่เทรนจาก Flatbed Scan เพียงอย่างเดียว

### 2.3 การแก้ปัญหาเฉพาะของฟอนต์และวรรณยุกต์ไทย (Fine-Grained Tuning)
- มีการเทรนครอบคลุมทั้ง **ฟอนต์มีหัว (Traditional Fonts)** และ **ฟอนต์ไม่มีหัว (Modern Loopless)**
- ปรับจูนการแก้ปัญหา **วรรณยุกต์ลอย/สระซ้อน** ในหนังสือยุคเก่า (เช่น หนังสือพิมพ์และเอกสารประวัติศาสตร์)
- โมเดลถูกออกแบบให้คืนค่า Reading Order ที่ถูกต้อง ทำให้คำเชื่อมประโยคไม่หลุดหาย

## 3. ตารางเปรียบเทียบ: OpenThai OCR vs เจ้าอื่นๆ

| คุณสมบัติ | Tesseract 5 | EasyOCR / PaddleOCR | OpenThai OCR Text | OpenThai OCR Markdown | Cloud API ทั่วไป (เช่น Google/AWS) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **ความแม่นยำภาษาไทยพื้นฐาน** | ปานกลาง (มักสับสนสระ/วรรณยุกต์) | ดี | ดีเยี่ยม | ดีเยี่ยม | สูง |
| **ฟอนต์ไม่มีหัว (Kanit/Prompt)** | ตกหล่นบ่อย | มีสับสนตัวอักษรฐานคล้ายกัน | แม่นยำสูง | แม่นยำสูง | แม่นยำ |
| **โครงสร้างตารางและคอลัมน์** | เสียโครงสร้าง (Text เละ) | ได้เฉพาะ Box ต้องรวมเอง | ได้ Bounding Box + ลำดับอ่าน | **แปลงเป็น HTML Table / Markdown สมบูรณ์** | บางบริการมี Form Parser แยกต่างหาก |
| **การทำงานแบบ Offline / Private** | ทำได้ (เบา) | ทำได้ | **ทำได้ง่ายมาก (ไฟล์ ~5 MB, รันบน CPU)** | ทำได้ (รันผ่าน GGUF / llama.cpp / vLLM) | ทำไม่ได้ (ต้องส่งข้อมูลออกนอกเครื่อง) |
| **ความเร็วต่อหน้า** | ปานกลาง | ปานกลาง (ต้องการ GPU) | **เร็วมาก (~0.39s บน CPU)** | ขึ้นกับ GPU/ฮาร์ดแวร์ | ขึ้นกับ Network Latency |
| **ต้นทุน (Cost)** | ฟรี (Open-source) | ฟรี (Open-source) | **ฟรี (Open-weight: Apache-2.0)** | ฟรี (Open-weight: OpenMDW) | เสียเงินตามจำนวนหน้า/Request |

## สรุปภาพรวม

เหตุผลหลักที่ **OpenThai OCR แม่นยำกว่าเจ้าอื่นๆ** ประกอบด้วย:
1. **Localization แท้จริง:** ไม่ใช่แค่การนำ Multi-language Model ทั่วโลกมา Detect แต่เป็นการเทรน Output Layer และ Vocabulary ให้สอดคล้องกับพยัญชนะ สระ และวรรณยุกต์ไทย
2. **แก้ปัญหา Document Layout แบบครบวงจร:** ด้วยเวอร์ชัน Markdown ทำให้สามารถแปลงเอกสารราชการและตารางซับซ้อนให้กลายเป็น Structured Data สำหรับระบบ RAG และ LLM ได้ทันที
3. **น้ำหนักเบาและประมวลผล Local ได้ 100%:** เอกสารสำคัญหรือเอกสารทางการเงิน/กฎหมายไม่ต้องส่งขึ้น Cloud และทำงานได้เร็วกว่าโมเดลขนาดใหญ่ทั่วไปบนเครื่องธรรมดา
